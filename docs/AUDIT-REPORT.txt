요청 사항 종합 검증 보고서 — 2026-11-22

결론
기존 48개에서 153개 실행 사례로 검사를 확대했다.
수정 후 실패 0, 건너뜀 0. 아래 자동 검증 범위에서 요청한 동작을 확인했다.
이번에 발견한 3종의 결함을 수정했다. 실제 OS 창의 수동 조작까지 검증한 결과는 아니다.

요청별 확인 결과
1. 슬라이더/세대 번호/특정 간격/처음·최신 이동: 통과.
   슬라이더 드래그 중 정지, 놓을 때 복원, 저장 경계에서 멈춤, 잘못된 입력 거부.
2. 1000개 고정 보관/사용자 설정 제거: 통과.
   20000회 비반복 진행에서도 최신 1000개만 보관하고 절대 번호를 유지.
   작은 용량, 999/1000 경계, 보관 범위 시작이 0이 아닌 경우도 검사.
3. 보드 전체 반복 감지: 통과.
   Blinker/고정 블록/과도 구간/Glider+Blinker 조합을 구분.
   셀 수나 모양만 같고 좌표가 달라지는 Glider를 반복으로 오인하지 않음.
4. 반복 감지 후 저장 중단, 현재 번호와 보드 변화 계속: 통과.
   반복 감지 직전까지 보관. 탐색/재생을 반복해도 범위가 늘어나지 않도록 보완.
   1000보다 긴 주기 검사는 합성 결정적 보드로 실시. 긴 주기는 첫 재등장보다 늦게
   감지할 수 있다는 기존 정책은 유지하며 실제 감지 시점 직전까지만 보관.
5. 고정/빈 보드의 세대 번호 정지: 통과.
   처음부터 고정된 보드는 0세대, 단독 셀 소멸은 1세대에서 멈춤.
   실제 Swing 타이머 자동 정지, +1세대 무증가, 편집 후 재시작 확인.
6. +1세대 문구 및 동작: 통과.
   다음 저장 기록이 있으면 편집 내용 포함 복원, 저장 끝에서만 새 계산.
7. 현재 번호가 저장 범위를 넘을 때 이동 입력칸에 마지막 저장 번호 표시: 통과.
   현재 100/저장 0~1에서 상단 100, 입력칸 1. 이후 편집 시 새 범위 100~100 갱신.
8. 과거 편집의 정확한 분기: 통과.
   0~20 중 10 편집 시 0~9 보존/10 교체/11~20 삭제/최신 10, 새 11부터 계산.
9. 편집 후 15세대 진행 → 편집 직전으로 복귀 → +1세대: 통과.
   추가한 고정 블록과 10~25세대 상태 보존, 끝에서 26세대 신규 계산.
   연속 자동 실행도 같은 경계를 지나며, 재편집할 때만 미래를 삭제.
10. 편집 이전 기록과의 잘못된 반복 판정 방지: 통과.
    과거 위치로 이동시킨 Glider를 계속 저장. 새 분기 안의 진짜 반복은 감지.
11. 기존 Life 규칙/원본 파일 형식/격자 경계 복원: 자동 검사 통과.
    실제 파일 선택기 취소/오류/메뉴 동작의 네이티브 UI는 별도 미검증.
12. 실행 안내/코드 위치/회의 설명/테스트 자료: 최신 동작으로 갱신.

이번에 찾아 수정한 문제
A. 반복 감지 후 탐색·재생하면 저장 범위가 늘어남.
   Blinker를 다시 재생하자 0~1이 0~2로 증가하는 실패를 재현했다.
   원인: seek가 반복 판정/탐지 진행을 매번 지웠음.
   수정: 탐색·재생은 동일한 기록이므로 분석 결과를 보존하고 편집/초기화 때만 폐기.
B. 안정된 마지막 상태를 재생해도 정지 표시가 즉시 돌아오지 않음.
   안정 판정도 기록과 함께 보존하고 해당 끝 상태로 돌아오면 바로 적용.
C. 간격에 1.5/10abc/1e2를 넣으면 1/10/1로 이동함.
   Swing 숫자 파서가 앞부분만 해석하는 문제를 재현했다.
   수정: 문자열 전체가 1~1000 정수인지 검사. 잘못된 입력은 위치/기록을 변경하지 않음.

배포 검증
이번에도 최종 배포 후보 ZIP을 별도 디렉토리에 풀고, 다시 빌드하지 않은 실행 JAR로

최종 JAR이 검사한 JAR과 바이트 단위로 일치함을 확인했다.
