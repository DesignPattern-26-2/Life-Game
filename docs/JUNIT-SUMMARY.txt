1. JUnit이란?
Java 코드가 예상대로 동작하는지 자동으로 확인하는 테스트 프레임워크다.
테스트 코드에서 상황을 준비하고, 기능을 실행한 뒤, 실제 결과와 기대값을 비교한다.
@Test는 테스트 메서드를 지정하고, assertEquals 등의 검증문은 결과를 비교한다.
@ParameterizedTest는 같은 검사를 여러 입력값으로 반복한다.
이번 검사는 개별 클래스 검사뿐 아니라 보드·타임라인·타이머의 연동 검사도 포함한다.

2. 실행 파일과 위치
프로젝트 폴더:
/Users/nayoung/Documents/Codex/2026-11-20/holub-life-game-6-2/outputs/Life-Game-timeline

전체 실행 스크립트: test.sh
검사 대상 프로그램: src/com/holub/life/ 아래 Java 코드
테스트 코드: tests/com/holub/life/ 아래 Java 코드
JUnit 실행기: lib/junit-platform-console-standalone-1.11.4.jar
버전: JUnit Jupiter 5.11.4 / JUnit Platform 1.11.4
검증 환경: macOS, JDK 26.0.2.1, Java 17 대상으로 컴파일

터미널 실행:
cd "/Users/nayoung/Documents/Codex/2026-11-20/holub-life-game-6-2/outputs/Life-Game-timeline"
sh test.sh

test.sh는 다음 작업을 자동으로 수행한다.
① build.sh로 프로그램 소스를 컴파일하고 실행 JAR을 만든다.
② tests/의 Java 파일을 컴파일해 build/test-classes에 저장한다.
③ JUnit 실행기가 테스트를 찾아 실행하고 성공·실패를 출력한다.
④ XML 결과를 build/test-results/에 저장한다.
게임 창을 켜서 사람이 누르는 방식이 아니라, 창을 띄우지 않는 headless 모드에서
프로그램 상태와 Swing 버튼·슬라이더·실제 타이머의 동작을 코드로 검사한다.

현재 로컬 폴더에는 JUnit 실행기가 포함되어 있다.
GitHub에서 새로 내려받으면 lib/*.jar는 Git 제외 대상이므로 실행기가 없을 수 있다.
이 경우 docs/DEPENDENCIES.txt에 있는 JUnit 다운로드 주소에서 받아 lib/에 넣는다.

4. 핵심 재현 시나리오
0~20세대 저장 → 10세대 편집 → 10 교체 및 기존 11~20 삭제 → 새 11~25 저장
→ 9세대로 복귀 → +1세대/자동 실행으로 편집된 10~25 복원 → 새 26 계산.
편집한 셀의 자연 소멸과 기록 유실을 구분하기 위해 고정 블록을 추가해 추적했다.
이 밖에 Blinker의 저장 범위 고정, 빈 보드/고정 패턴의 세대 정지,
1000개 한도와 저장 범위 밖 실행 시 이동 입력칸 표시를 확인했다.

5. 결과와 수정 사항
기존 48개에서 153개로 확대했고, 최종 153개 성공 / 실패 0 / 건너뜀 0.
배포 후보 ZIP을 별도로 풀고 재빌드 없이 그 안의 실행 JAR에 대해서도
동일한 153개 검사를 실행해 모두 통과했다.
배포 JAR 검사에서는 JUnit의 --class-path를
build/Life-Game-timeline.jar:build/test-classes로 지정했다.

검사 과정에서 편집 기록 유실·잘못된 반복 판정 등의 회귀를 확인했고,
최종 확대 검사에서는 다음 세 문제를 재현한 뒤 수정했다.
- 반복 감지 후 탐색·재생하면 저장 범위가 늘어나는 문제.
- 안정된 마지막 상태로 복귀해도 정지 상태가 즉시 복원되지 않는 문제.
- 간격 입력 1.5/10abc/1e2의 앞부분만 숫자로 받아들이는 문제.

6. 결과 파일과 한계
docs/test-results.txt: 최종 배포 JAR의 JUnit 실행 로그.
build/test-results/: test.sh 실행으로 생성된 XML 결과.
docs/TEST-CASES.txt: 세부 검사 목록.
docs/AUDIT-REPORT.txt: 요청별 결과 및 별도 성능 측정.
docs/DELIVERY-VERIFICATION.txt: 배포 파일 검증 근거.

실제 macOS 창의 마우스·메뉴·파일 선택기 조작, Windows 실행,
다른 팀원 기능과 통합한 상태는 별도 확인이 필요하다.
성능 측정은 별도의 벤치마크이며 JUnit 153개에 포함되지 않는다.
이 문서는 기존 결과를 정리한 것으로, 작성일에 테스트를 새로 실행한 것은 아니다.
