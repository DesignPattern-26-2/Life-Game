LifeHistoryTest (27개)
- Blinker 1001세대 계산: 반복은 2세대에서 감지, 보관은 0~1/2개 고정,
  실제 보드 방향과 현재 세대는 계속 맞는지 확인.
- 정지 블록/빈 보드는 0세대 유지, 단독 셀 소멸 후에는 1세대에서 멈춤.
- 안정 상태 이후 100번 진행 요청에도 번호/저장 수 유지.
- 안정 상태에서 편집하면 재평가. 과거로 이동하면 기록을 재생하고 안정된 끝에서 즉시 정지.
- 고정 블록+Blinker+소멸할 셀을 섞어 전체가 반복되기 전 오인하지 않는지 확인.
- Glider+Blinker 혼합은 위치가 바뀌므로 전체 반복으로 오인하지 않는지 확인.
- 실제 시뮬레이션 결과를 별도의 단순 Conway 규칙 계산기와 비교.
- 저장 경계 문제, Glider의 블록 경계 통과, 고정 난수 보드의 복원 후 재계산 회귀.
- 과거 편집 분기, 저장 범위 밖 현재 번호에서 편집, 반복 감지 이후 탐색/초기화.
- 0~20 보관 후 10세대의 Glider를 원래 8세대 위치로 편집:
  새 11세대가 과거 9세대와 같아도 반복 오인 없이 11~16세대 저장을 계속한다.
  이 검사는 수정 전 실제 실패했고 수정 후 통과했다. 9세대 보존/10세대 교체도 확인.
- 10세대를 Blinker로 편집하면 새 분기 안의 진짜 주기 2는 여전히 감지한다.
- 자동 실행과 같은 advance 호출로 편집 경계를 통과해도 기록 재생/보존.
  재생 도중 다시 셀을 편집했을 때만 이후 기록을 삭제하고 새 분기를 생성.
- 잘못된 번호 입력은 보드/현재 상태를 바꾸지 않음.
- 원본 .life 저장 형식의 왕복과 새 히스토리 시작.
- 보드 변경 후 과거 스냅샷 불변성, 좌표가 다른 동일 개수 셀의 불일치.

TimelinePanelTest (8개)
번호/간격/처음/최신 이동과 자동 정지 호출,
슬라이더 드래그 중 정지 및 해제 후 복원, 모델 갱신의 재귀 이벤트 방지,
실행/정지/+1세대 연결, 사용자 저장 한도 입력 제거 및 고정 1000 확인,
Blinker의 현재 100세대/저장 0~1에서 상단은 100, 이동 입력칸은 1 표시 및 '이동'으로 복귀.
안정 상태 감지 시 정지 콜백 호출, 실행/+1세대로 증가하지 않음, 편집 후 실행 재개.
번호 입력으로 10세대 이동 후 편집: 슬라이더 최대/입력/표시가 즉시 10으로 갱신,
저장 범위 0~10, 다음 버튼 비활성, 구 11세대 접근 불가, 편집 상태 복원,
+1세대 후 슬라이더/번호가 새 11세대로 갱신됨을 headless Swing에서 검사.
사용자가 보고한 재현 순서: 10세대에 영구 블록 추가 → 15세대 더 진행 →
슬라이더로 9세대 이동 → +1세대로 10~25 왕복 검사.
편집한 셀/각 세대 상태와 최대 범위 25가 보존되고, 끝에서 새 26세대가 생성됨을 확인.
이 검사는 수정 전 10세대의 셀이 사라져 실패했고 수정 후 통과했다.
