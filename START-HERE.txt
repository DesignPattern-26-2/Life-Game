2. 이번 변경
- 보드 전체의 위치별 생존 상태가 과거와 정확히 일치하면 반복으로 판정한다.
- 반복을 처음 감지한 세대부터 저장하지 않는다. 상태가 바뀌는 반복 패턴은 계속 진행한다.
- 예: 초기 Blinker는 2세대에 0세대와 같아진다. 저장 범위는 0~1, 저장 수는 2개.
  현재 세대는 2, 3, 4…100…으로 계속 올라가며 보드도 가로/세로로 바뀐다.
- 다음 상태에 셀 변화가 없으면 세대 번호를 증가시키지 않고 안정 상태로 자동 정지한다.
  처음부터 고정된 보드는 0세대, 1세대에 모두 죽는 보드는 1세대에서 멈춘다.
  안정 상태에서 +1세대를 눌러도 번호는 증가하지 않는다. 편집/초기화 후 재평가한다.
  이전 기록을 탐색하면 그 상태를 복원하고, 안정된 마지막 상태에 도달하면 즉시 정지한다.
  다른 패턴이 움직이고 있으면
  정지 부분이나 일부 Blinker가 같다는 이유만으로 전체 저장을 멈추지 않는다.
- 이동 중인 Glider는 같은 모양이어도 좌표가 다르므로 반복으로 보지 않는다.
- 저장 한도는 앱에서 1000개로 고정했다. 한도 설정 입력/버튼은 제거했다.
- '1세대 계산'을 '+1세대'로 변경했다.

3. 조작
실행: 150ms 간격 진행. 원본 Go 메뉴의 속도 선택도 유지.
정지: 자동 계산 정지. +1세대: 다음 저장 세대를 복원하고, 저장 끝에서만 새 상태를 계산한다.
자동 실행도 저장 기록부터 재생한다. 새 계산에 변화가 없으면 세대가 증가하지 않는다.
슬라이더: 드래그 시 자동 정지, 놓을 때 저장 상태 복원.
세대 번호 + 이동/Enter: 저장 범위 내 번호로 이동.
현재 세대가 저장 범위를 넘으면 이동 입력칸에는 마지막 저장 세대를 표시한다.
상단 현재 세대는 실제 진행 번호를 계속 표시한다.
간격 + 이전/다음: 지정 간격으로 저장 범위를 탐색하며 경계에서 멈춤.
처음/최신: 저장된 가장 오래된/가장 새로운 세대.
현재 번호가 저장 범위를 넘어섰으면 '최신'으로 저장 끝 지점에 돌아갈 수 있다.
슬라이더는 저장 범위만 나타내므로 반복 중에는 오른쪽 끝에 머무를 수 있다.
Grid > Load에서 examples/blinker.life, boundary-blinker.life, glider.life 사용.

4. 기록/분기 정책
초기 보드는 0세대. 최대 1000개의 연속된 보드를 메모리에 저장한다.
아직 반복을 감지하지 못하면 1000개를 넘을 때 가장 오래된 기록부터 삭제한다.
기록 삭제 후에도 세대 번호는 실제 번호를 유지한다.
반복 감지 후에는 저장 범위의 시작과 끝 모두 고정된다.
탐색·+1세대·실행은 기존 기록을 보존한다. 셀 편집 시에만 이후 기록을 폐기한다.
예: 저장 0~20에서 10세대 편집 → 0~9 보존, 10은 편집 상태로 교체,
11~20 삭제, 최신 저장 번호는 즉시 10. 이후 새 11세대부터 계산/저장한다.
편집 후 25세대까지 진행한 뒤 9세대로 돌아가 +1세대를 누르면,
편집된 10세대를 복원하고 11~25세대 기록도 유지한다. 25세대 끝에서만 새 26세대를 계산한다.
이전 구현은 9세대로부터 재계산해 편집된 10세대 이후를 덮어썼으나 수정했다.
편집 전 기록은 탐색용으로만 보존하고 새 실행 구간의 반복 판정에서는 제외한다.
이전 구현은 새 11세대가 편집 전 9세대와 같으면 반복으로 오인할 수 있었으나 수정했다.
편집/새 게임 시 반복 감지는 초기화한다. 탐색과 재생은 기존 반복 판정을 보존한다.
반복을 감지한 기록을 여러 번 재생해도 저장 범위가 불필요하게 늘어나지 않는다.
반복 실행으로 현재 번호가 저장 범위를 벗어난 상태에서 셀을 편집하면,
저장되지 않은 시간 간격이 생기므로 그 현재 번호에서 새 기록 구간을 시작한다.
예: 현재 100세대, 저장 0~1에서 편집 → 새 저장 범위 100~100.
기존 기록을 유지하며 분기하려면 먼저 슬라이더나 '최신'으로 저장 세대에 돌아가 편집한다.
Clear와 성공한 Load는 새로운 0세대. Store는 현재 보드만 원본 .life 형식으로 저장한다.
앱 종료 후 히스토리 복구나 여러 분기 동시 보관은 지원하지 않는다.

5. 메모리/반복 탐지
BoardSnapshot은 원본 Cell.Memento 인터페이스를 구현한 비트 기반 메모리 전용 상태다.
64×64 = 4096비트 = 상태당 셀 데이터 512바이트.
1000개는 셀 비트 데이터 약 500KiB이며, 객체 오버헤드와 탐지 기준 상태 등은 별도다.
원본 파일 저장 형식은 변경하지 않았다.
최근 기록과 정확한 상태 비교로 짧은 주기를 즉시 감지한다.
저장 한도보다 긴 주기는 기준 상태 한 개를 유지하는 Brent 감지기로 보완한다.
긴 주기는 첫 재등장보다 늦게 감지될 수 있으며, 실제 감지 세대의 직전까지 저장한다.
해시값/셀 개수만으로 판정하지 않으므로 충돌이나 단순 이동을 반복으로 오인하지 않는다.
규칙/보드 크기/경계 조건이 바뀌면 다른 팀 기능에서 반드시 새 히스토리를 시작해야 한다.

6. 코드 읽기
GenerationHistory: 고정 용량, 연속 기록, 탐색/분기/정확한 상태 검색.
BoardSnapshot: BitSet으로 저장한 불변 상태, 원본 Memento 인터페이스 재사용.
CycleDetector: 긴 주기를 탐지하는 단일 기준 상태 방식.
LifeHistory: 실제 세대 번호와 마지막 저장 세대를 분리하고 반복 감지/진행/복원 연결.
TimelinePanel: 입력, 반복 감지 표시, +1세대, 저장 범위 슬라이더.
Universe: 클릭/Load/Clear와 history 연결.
Clock/Life: Swing 이벤트 스레드에서 계산·편집·표시를 순서대로 처리.
Neighborhood: 상태 복원 후 계산 캐시 초기화(기존 경계 누락 문제 수정).
